# 输出与布局约定

## 帧基线必须已完整写出

`write_diff` 读取当前帧和最后一个完整写出的帧，不修改它们。调用方将结果写到终端；若写入被中断，保留尚未写出的字节继续写，或丢弃差分基线并用 `previous=None` 全量重画。不要把只写了一部分的当前帧作为新基线。

帧的行高来自 `Frame::size().rows`。`Frame::row(index)` 必须为范围内每一行返回有效字符串；当布局含分栏时，行必须已完成拼接和宽度限制。终端模式属于调用方声明的 `Modes`，库不会探测或恢复终端先前状态。

`same_layout` 默认比较尺寸。分栏改变而终端尺寸不变时，调用方可额外比较布局结构；SSMCP 比较自己的完整 `Geometry`，保持原有重画规则。

## 文字宽度由调用方决定

字节数、Unicode 字符数和显示列数不是同一个量。`Row` 接受可见列数，检查目标宽度，然后补 ASCII 空格。超宽返回 `TooWide`，不写任何内容；输出设备拒绝写入则返回 `Output`，此时设备可能已收到部分字节。

库不裁剪 grapheme，不维护宽字符表，不解析 OSC，也不接收任意终端控制流。`Frame` 行可以包含可信 SGR 样式；调用方必须过滤移动光标、换行、清屏及其它会逃出行边界的控制序列。需要全宽背景时，应在渲染每个单元或补齐空格前设定背景色。

SSMCP 的 Activity 行先经有界 cell normalization，再用安全的单元序列化器生成字形和 SGR；这个应用层步骤保留图片半块的显式背景，并将空白补到分栏边界。它不是 ztuio 内置的 Unicode/终端模拟器。

## 复杂度与资源

库没有 heap allocator、全局可变状态、OS I/O、线程或锁。帧差分在行数与被比较的文本字节数上是线性的，除调用方输出之外使用常量辅助空间。相等行比较仍然需要读字符串；零分配不意味着零计算。

`write_spaces` 按固定长度的静态空格片段写入，不构造重复字符串。调用方仍应对需要写出的宽度和总帧大小设限。几何坐标使用 `u16`；矩形的排他边界必须可表示，构造时检查溢出。

## 测试覆盖与剩余边界

契约测试检查 ANSI 次序、不变帧、单行更新、尺寸和布局改变、模式/光标更新、输出缓冲错误、Unicode 宽度显式提供、行超宽拒绝、矩形溢出与分栏不重叠。应用层还需用真实终端或独立 VT 解码器检查背景、字体宽度和原生图片行为。

本库不承诺所有终端实现遵守同一套 Unicode、SGR 或 DEC 模式。ANSI 文本差分和 Kitty 等图像通道的写出次序，由上层协调。
